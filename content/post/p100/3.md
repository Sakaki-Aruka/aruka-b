# OS インストール

今回 OS には Ubuntu Server 24.04 を選択しました。  
記事作成時点 (2026-09-22) 時点で最新の Ubuntu 26.04 がリリースされていますが、少し古い NVIDIA GPU 向けのドライバを導入しなければいけない都合上、新しすぎる 26.04 では手間が増えると判断しあえて 24.04 を選択しました。  

また、 Ubuntu Server を選択しているのはリソース節約のためです。  
あくまでも記事作成者である私の環境では Server 版で問題なかったというだけのことですので、 CLI からの管理に不慣れであったりする場合には Desktop 版を選択しても問題ありません。

# ドライバインストール

NVIDIA GPU 用のドライバは AMD や Intel の GPU と異なり Linux のカーネルに組み込まれていないので、追加でインストールしてやる必要があります。  

また、OS インストールのセクションでも書きましたが今回はお世辞にも新しいとは言えない P100 というハードを扱うため、最新のバージョンからかなり離れた NVIDIA の 580 系ドライバを利用します (P100 が属する Pascal アーキテクチャファミリはのフルサポートは 580 系が最後であるため)。  

---

まずドライバをインストールする前に BIOS / UEFI の `Secure Boot` が無効化されているかを確認してください。有効化されていても問題ありませんが、パスワードを設定する必要が出てくるので無効化して手間を省いておくことを推奨します。  

Secure Boot 有効時にはドライバのインストール中に以下のような画面が表示され、パスワードを設定させられます。  
![](/post/p100/3/secure-boot-prompt.png)

次に以下のコマンドでドライバのインストールを行います。  

```bash
sudo apt update
sudo apt install -y build-essential dkms linux-headers-$(uname -r)

sudo apt install nvidia-headless-580-server nvidia-utils-580-server
# nvidia-headless-580-server の箇所は、 Desktop 版を利用していれば nvidia-driver-580-server を利用しても良い

sudo systemctl reboot

# ---
# 再起動後、以下のコマンドを実行して導入されているかを確認する
nvidia-smi
```

私が環境を構築した時点ではドライババージョン `580.178.04` がインストールされました。  

# llama.cpp インストール

ドライバをインストールしたら次は LLM を動かすためのエンジンをインストールします。  
今回は導入が比較的用意な [llama.cpp](https://github.com/ggml-org/llama.cpp) を利用しますが、ここからは完全に好みで構築することも可能です。  

今回は P100 での動作に最適化させるため llama.cpp をソースコードからビルドします。  

---

ビルドするスクリプトを作成したので、これを実行してください。  
以下のスクリプトでは、ホームディレクトリ配下の llama.cpp ディレクトリへ展開します。  
LLAMA_DIR を書き換えることで展開先を変更することができます。  

```bash
#!/usr/bin/env bash
#
# Tesla P100 (Pascal, sm_60) 向け llama.cpp CUDA バックエンド セットアップスクリプト
#
# 前提:
#   - NVIDIAドライバ(580系)は導入済み・nvidia-smiで動作確認済みであること
#   - CUDA 13.x はPascal向けコード生成を削除しているため、ここではCUDA Toolkit 12.6を
#     「toolkitのみ」インストールする(既存ドライバは上書きしない)
#
# 使い方:
#   chmod +x setup_llama_cpp_p100.sh
#   ./setup_llama_cpp_p100.sh
#
set -euo pipefail

CUDA_VERSION="12-6"
CUDA_DIR="/usr/local/cuda-12.6"
LLAMA_DIR="${HOME}/llama.cpp"
GPU_ARCH="60"   # Tesla P100 = compute capability 6.0

log() { echo -e "\n\033[1;32m==> $*\033[0m"; }

# ---------------------------------------------------------------------------
# 0. 足りないツールをインストール
# ---------------------------------------------------------------------------
sudo apt install -y cmake

# ---------------------------------------------------------------------------
# 1. CUDA Toolkit 12.6 (toolkitのみ、ドライバは触らない)
# ---------------------------------------------------------------------------
if [ -d "${CUDA_DIR}" ]; then
    log "CUDA 12.6 は既に ${CUDA_DIR} に存在するのでスキップ"
else
    log "CUDA keyring を追加"
    TMP_DEB="$(mktemp --suffix=.deb)"
    wget -qO "${TMP_DEB}" \
        https://developer.download.nvidia.com/compute/cuda/repos/ubuntu2404/x86_64/cuda-keyring_1.1-1_all.deb
    sudo dpkg -i "${TMP_DEB}"
    rm -f "${TMP_DEB}"

    log "CUDA Toolkit ${CUDA_VERSION} をインストール"
    sudo apt update
    sudo apt install -y "cuda-toolkit-${CUDA_VERSION}"
fi

# ---------------------------------------------------------------------------
# 2. PATH / LD_LIBRARY_PATH を ~/.bashrc に追記(重複防止)
# ---------------------------------------------------------------------------
log "PATH / LD_LIBRARY_PATH を設定"
BASHRC="${HOME}/.bashrc"
MARK="# >>> cuda-12.6 for P100 >>>"
if ! grep -qF "${MARK}" "${BASHRC}" 2>/dev/null; then
    {
        echo "${MARK}"
        echo "export PATH=${CUDA_DIR}/bin:\$PATH"
        echo "export LD_LIBRARY_PATH=${CUDA_DIR}/lib64:\$LD_LIBRARY_PATH"
        echo "# <<< cuda-12.6 for P100 <<<"
    } >> "${BASHRC}"
fi
export PATH="${CUDA_DIR}/bin:${PATH}"
export LD_LIBRARY_PATH="${CUDA_DIR}/lib64:${LD_LIBRARY_PATH:-}"

log "nvcc バージョン確認"
nvcc --version

# ---------------------------------------------------------------------------
# 3. llama.cpp を取得してビルド(sm_60固定)
# ---------------------------------------------------------------------------
if [ -d "${LLAMA_DIR}" ]; then
    log "llama.cpp は既に ${LLAMA_DIR} にあるので git pull"
    git -C "${LLAMA_DIR}" pull
else
    log "llama.cpp を clone"
    git clone https://github.com/ggml-org/llama.cpp "${LLAMA_DIR}" --depth 1
fi

log "llama.cpp をビルド (CUDA, sm_${GPU_ARCH})"
cmake -B "${LLAMA_DIR}/build" -S "${LLAMA_DIR}" \
    -DGGML_CUDA=ON \
    -DCMAKE_CUDA_ARCHITECTURES="${GPU_ARCH}"
cmake --build "${LLAMA_DIR}/build" --config Release -j"$(nproc)"

# ---------------------------------------------------------------------------
# 完了
# ---------------------------------------------------------------------------
log "セットアップ完了"
echo "実行例(P100 = nvidia-smi上のGPU 1 を明示指定):"
echo ""
echo "  CUDA_VISIBLE_DEVICES=1 ${LLAMA_DIR}/build/bin/llama-server \\"
echo "      -m /path/to/model.gguf -ngl 999 --port 8080"
echo ""
echo "新しいシェルを開くか 'source ~/.bashrc' でPATH設定を反映してください。"
```

HP Z440 での実行で 15 分ほどかかりました。

# おまけ・電力制限をかける

P100 は TDP (最大消費電力) が 250W であり、推論など負荷の高いタスクを振ると実際にこの程度の電力を消費します。  
ですが、消費電力に制限をかけてもそれほど性能は低下しません。  
逆に消費電力を抑えられるので同時に発熱も抑えることができます。  
それによってファンの回転数を下げることができ、(多少ですが) 動作音を小さくすることができます。  

以下の systemd unit とスクリプトでは GPU の最大消費電力が 150W 程度になるよう設定しています。  
(何通りかの電力制限で測定したところ 150W あたりが消費電力と性能の比率が最も高くなったので採用しました。P100 自体は 125W まで制限できるようです。)

このサービスを起動時に自動実行されるよう設定しておくことを推奨します。  

```
[Unit]
Description=Apply persistence mode + 150W power limit to all Tesla P100 GPUs
After=nvidia-persistenced.service
Wants=nvidia-persistenced.service

[Service]
Type=oneshot
ExecStart=<スクリプトのファイルパス>
RemainAfterExit=yes

[Install]
WantedBy=multi-user.target
```

```
#!/bin/bash
# Apply persistence mode + a fixed power limit to every attached NVIDIA Tesla P100 GPU.
# Selects GPUs by name (not index) so it stays correct even if PCI enumeration order
# changes or more P100s are added. Intended to run as root (e.g. via systemd);
# run with sudo if invoked manually.
set -eu

TARGET_PL_WATTS=150

nvidia-smi --query-gpu=name,uuid --format=csv,noheader | while IFS=',' read -r name uuid; do
  name=$(echo "$name" | xargs)
  uuid=$(echo "$uuid" | xargs)
  case "$name" in
    *P100-*)
      echo "Applying settings to $name ($uuid)"
      nvidia-smi -i "$uuid" -pm 1
      nvidia-smi -i "$uuid" -pl "$TARGET_PL_WATTS"
      ;;
  esac
done
```

# Java について解説

Java（ジャヴァ）は、**オブジェクト指向のプログラミング言語**です。  
「**どこでも動く**」ことを目指して設計されており、OS やハードウェアに依存しにくいため、サーバーやデスクトップ、モバイル、エントリレベルシステムなど、幅広い分野で使われています。

---

## 1. Java の特徴

### ① クロスプラットフォーム（どこでも動く）
Java は **JVM（Java Virtual Machine）** という仮想マシンの上で動作します。

- 一度コンパイルすると、同じソースコードを Linux / Windows / macOS など、異なる環境でも同じように実行できます。
- 「Write once, run anywhere（一度書く、どこでも動かせる）」が有名な理念です。

```text
Java ソースコード
   ↓
コンパイル
   ↓
Bytecode（バイトコード）
   ↓
JVM
   ↓
実行
```

---

### ② オブジェクト指向
Java はオブジェクト指向の言語です。  
オブジェクト指向とは、プログラムを**オブジェクトの集合**として考える設計思想です。

主要な概念：

- **クラス（Class）**
  - オブジェクトの型やテンプレート
- **オブジェクト（Object）**
  - クラスから作られた実体
- **継承（Inheritance）**
  - クラス同士で構造を共有する仕組み
- **多態（Polymorphism）**
  - 同じ呼び出しでも、オブジェクトによって違う動作をできる仕組み
- **カプセル化（Encapsulation）**
  - 内部状態を外部から直接触れなくして安全に管理する仕組み

---

### ③ 自動メモリ管理（Garbage Collection）
C や C++ で手動メモリ管理が必要な部分とは異なり、Java は**ゴミ収集機構**で不要なメモリを自動的に回収します。

- メモリ漏れは起きにくい
- 開発がしやすい
- ただし、GC が動作するタイミングやパフォーマンス特性は意識すること

---

### ④ 安全な言語（Safe Language）
Java は C 系言語と違って、以下のような危険な操作を基本的に禁止しています。

- ポインター直接操作
- 任意のメモリ書き込み
- 危険な型強制

そのため、**セキュリティや安定性を重視したシステム開発**に向いています。

---

## 2. Java の実行方法

### Java の基本的な流れ
```text
source code (.java)
      ↓
javac
      ↓
class file (.class)
      ↓
java (JVM)
```

つまり、Java は **コンパイル型言語**です。  
ソースコードをまずバイナリコードに変換してから実行します。

---

## 3. 最小サンプルコード

### 1. 出力だけ

```java
public class Main {
    public static void main(String[] args) {
        System.out.println("Hello Java!");
    }
}
```

実行:
```bash
javac Main.java
java Main
```
出力:
```text
Hello Java!
```

    }

```

出力:

```

## 5. クラスの仕組み

### クラスとは？
クラスは「**オブジェクトの型**」です。

```java
public class Car {
    private String color;
    private int speed;

    public Car(String color, int speed) {
        this.color = color;
        this.speed = speed;
    }

    public void accelerate(int amount) {
        speed += amount;
    }

    public void printInfo() {
        System.out.println(color + "の車が " + speed + " です");
    }
}
```

使用例:

```java
Car c = new Car("赤", 50);
c.accelerate(10);
c.printInfo();
```

---

### ② メソッド（Method）
オブジェクトの「**動作**」を表します。

```java
public void accelerate() { }
```

### ③ フィールド（Field）
オブジェクトの「**状態**」を表します。

```java
private int speed;
```

---

## 6. Java の主要な概念

### ① 継承（Inheritance）
親クラスの機能を子クラスで拡張します。

```java
public class Animal {
    public void eat() {
        System.out.println("食べる");
    }
}

public class Dog extends Animal {
    public void bark() {
        System.out.println("汪");
    }
}
```

---

### ② インターフェース（Interface）
「**こういう形式で振る舞え**」という契約を表現します。

```java
public interface Flyable {
    void fly();
}

public class Bird implements Flyable {
    public void fly() {
        System.out.println("飛ぶ");
    }
}
```

---

### ③ 多態（Polymorphism）
同じインターフェースや親型を持つオブジェクト群を、同じ呼び出しで処理できるようにできます。

```java
Animal[] animals = new Animal[] {
    new Dog(),
    new Cat()
};
```

このように、**同じ型として扱うことで設計が柔軟**になります。

### ③ ジェネリック（Generics）

### ④ Lambda と Stream

## 9. Java と他の言語との違い

### Java vs C / C++
- Java はメモリ管理が自動
- ポインタを直接使えない
- 実行環境が JVM
- 開発しやすい一方で、実装詳細の制御は弱い

### Java vs Python
- Java は型付けが厳しめ
- コンパイル型言語
- 大規模システム向き
- Python より起動や型安全の観点で堅実

### Java vs JavaScript
- 名前が似ていますが、完全に別の言語です
- JavaScript は Web 中心、動的型
- Java は JVM 上での型付け・オブジェクト指向設計が強い言語
