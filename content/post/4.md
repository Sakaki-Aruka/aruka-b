# はじめに

こんにちは、あるかです。  

タイトルにもある通り、自分が管理しているネットワークに導入していた Tailscale を NetBird に置き換えたので、その話をしたいと思います。  
主な用途は、Minecraft サーバーのプロキシを載せている VPS と自宅マシンの間の通信、そして外部から ProxmoxVE のクラスタなどにアクセスすることです。今回はこの前提で話を進めます。  

# 経緯

`resolv.conf` を書き換えられることにもやもやしていましたし、SSO は危なくないか?とも感じていました。そんな折に Twitter で少し(マイナスな方向で)話題になっているのを見て、これを機に置き換えてしまおうと考えるに至ったわけです。  

# 選定

まずは移行先の候補として HeadScale, Nebula, NetBird の 3 つを挙げ、次の 2 点を軸に選定しました。  

- どんな環境からでも相手に接続できるか
- セルフホスト時のメモリ使用量

まず HeadScale です。これは Tailscale のサーバー部分のコミュニティ実装というべきもので、これまで使ってきた Tailscale のクライアントをほぼそのまま流用できるため候補の筆頭でした。  
しかし「更新のサイクルがクライアントと必ずしも一致するとは限らない」という弱点が最後まで気になり、候補から外しました。  
(クライアント側のアップデートに対応するためどうしても使いたい場面で、サーバー側の対応が追いつかず使えなくなる可能性を排除できないため)

次に Nebula です。セルフホスト時のサーバーのメモリ使用量が他と比べてダントツで低く、とても期待していました。  
しかし他の候補と異なりサーバーにリレー機能がなく、多段 NAT やモバイル回線からの接続確立がほぼ不可能だったため、候補から外しました。  

最後に NetBird です。セルフホスト時のサーバー側のメモリ消費量は他よりやや多め (公式の推奨は 2GB 以上) ですが、クライアントとサーバーが同じ組織によって開発されているため互換性や更新サイクルはある程度信頼できます。  
さらにリレー機能があり、直接接続ができない場合でも通信を継続できるため、求めていた条件をすべて満たすとして採用しました。  

# 作業

## ドメインを取得する

なくてもおそらく大丈夫ですが、管理画面へのアクセスやピア(マシン)の登録時にアドレスの入力が楽になります。  
Cloudflare, Google Domains (現 Squarespace Domains), 某ドットコムなどから取得します。  

## VPS を借りる

NetBird のサーバーを動かすための VPS を借ります。  
自宅サーバーで動かすことも可能ですが、今回は「家側でポートを開放しない Tailscale の後継」という位置づけでの導入なので、汚れ役は VPS に任せます。  

[さくらの VPS](https://vps.sakura.ad.jp/specification/) のメモリ 2GB プランを契約しました。  
```yaml
# スペック一覧
- CPU: vCPU 3 コア
- RAM: 2GB
- ROM: SSD 100GB
- OS: Debian 12
- Network: 100Mbps
```

(ネットワークの通信速度が少し遅いような気もしますが、このネットワーク経由でダウンロードのような負荷の高い処理はほぼ行わない想定です。そもそも自宅に引き込まれている回線も 100Mbps なので、ちょうどよいバランスだと考えています)

## セットアップ

[NetBird 公式のセルフホスト向けスタートアップページ](https://docs.netbird.io/selfhosted/selfhosted-quickstart)を見ながら進めます。  

- `jq`, `curl`, `docker` をインストールします (入っていない場合)
- 管理画面へのアクセスや登録時のアドレス解決のための DNS レコードを設定します。
  - A レコード, 名前を netbird, コンテンツを VPS のグローバル IP アドレスにしました。
  - Cloudflare の場合はプロキシの状態をオフにして「DNS のみ」と表示されるようにする必要があります。
- インストールスクリプトを動かします
  - リバースプロキシを選択します。特にこだわりがなければデフォルトの `Traefik` で問題ありません。
  - NetBird Proxy を有効にするか選びます (今回は `No` にしました)。NetBird 網内で立てたサービスを外へ公開するときに便利な機能のようです。

ここまでの設定を行うと `config.yaml`, `dashboard.env`, `docker-compose.yml` が生成されているので、  

```
docker compose up -d
```  

でサーバーを立ち上げます。  

あとはページにアクセスしてユーザーを作成するだけで使い始めることができます。

## 移行作業

移行作業自体は思っていたほど大変ではありませんでした。  
1. NetBird の WebUI から Add Peer
2. Server を選択

この 2 つの操作を行うと、インストールコマンドと認証用のコマンドが表示されるので、それらを必要なマシンの台数分実行するだけでインストールが完了します。拍子抜けするほど手軽でした。  
また、通信の制限を設定するポリシーも、設定ファイルをカリカリ書く必要はありません。UI 上で制限の対象・プロトコル・ポートなどを選び、名前をつけるだけで設定が完了します。  

# 最後に

Tailscale から全面的に移行して 2 週間程度が経ちますが、今のところほとんど不満に思うことはありません。  
モバイルアプリも手軽に使え、セルフホストの設定を入れることもできるので非常に重宝しています。

1 つだけ言わせてもらうと、ポリシーの対象に複数のピアを指定することはできず、そのような場合は必ずグループを作成して指定しなければならないという仕様がつらいところです。  
おそらく、ピアの追加・削除が頻繁に起こるため、単体でポリシーに指定できるようにすると内部的なルールの書き換え回数が増えて非効率になる、というのを避けたいのだと思います(公式に明言されているわけではありません)。  
だとしても、利用する側からすれば 1 回しか使わない組み合わせのためだけにグループを作成するのは煩わしいので、何らかの形で対応する機能が実装されないかな……と思っています。
